# Архитектура первой сборки

## Границы модулей

`shared/tools.json` — проверяемая сервером матрица инструментов. Клиент отображает доступность, но сервер не доверяет клиентским расширениям/параметрам. `engines.py` — адаптеры, не HTTP-обработчики. `worker.py` — отдельный процесс с ограничениями. `jobs.py` — SQLite-состояние и диспетчер. `main.py` — HTTP, сессии, проверка загрузки и владения. React не содержит серверных секретов.

Состояния: queued → running → done/error/cancelled. Успешный результат появляется только после фактической проверки выходного файла. Файлы пишутся в каталог случайного job ID под именами `000.ext` и т. д. Пользовательские имена используются только для отображения, не как пути файловой системы. Пароли не записываются в SQLite: только во временный закрытый manifest для процесса конвертации, который удаляется после задачи.

SQLite использует WAL и короткие транзакции. Подключения закрываются после каждого действия. При перезапуске прерванные running-задачи получают понятную ошибку; queued-задачи продолжаются. Одна API-реплика владеет очередью, иначе возможна гонка восстановления/обработки. Горизонтальное масштабирование отложено до отдельного брокера.

PDFium не вызывается из параллельных потоков общего процесса: каждая задача получает отдельный процесс. Отмена убивает группу процессов вместе с дочерним OCR/локальным LibreOffice. Статусы — настоящие, нет имитации прогресса по таймеру. Office-движок вызывается только по настроенному серверному адресу, пользовательский URL не принимается.

## Хранение

Исходник → закрытый временный каталог → результат. Результат доступен только подписанной cookie-сессии, владеющей задачей. Нет возможности скачать по одному лишь знанию job ID. Автоудаление включает DB-запись и каталог; endpoint отказывает сразу после expiry. «Мои задачи» — не постоянный аккаунт и не межустройственная история.

## Расширение

Добавление операции: запись каталога → валидация параметров → адаптер с контрактом `convert(tool, inputs, outdir, options, settings, progress)` → тест входного/выходного формата → при необходимости параметры UI. Не включать плитки неработающих операций как будто они доступны. Экспериментальные конвертации должны иметь явную маркировку и проверку качества.

## Внешний API

OpenAPI: `/api/openapi.json`. Для запросов записи передавайте `X-IMONSOFT-Client: web`, сохраняйте cookie, используйте тот же origin. POST `/api/v1/jobs`: multipart `tool`, `options` (JSON-строка), `files` (повторяемое поле). Ответ 202 с job ID. GET job, POST cancel, DELETE job и GET download проверяют владельца. API keys и сервисные аккаунты — следующий этап, не притворяться, что browser cookie является полноценной API-аутентификацией.

## Дополнения 0.2

`pipeline.py` — единый оркестратор single/batch/finishing. Адаптер `convert(tool, inputs, outdir, options, settings, progress)` возвращает путь и предупреждения; `pipeline.execute(...)` добавляет структурированный batch-итог. Вся последовательность выполняется внутри одного ограниченного subprocess, включая создание ZIP; общий timeout применяется ко всей пачке. `extra_engines.py` содержит новые PDF-адаптеры и не обращается к платным API.

SQLite мигрирует поле `batch_result` при запуске без удаления существующих таблиц. Состояние остаётся `done`, когда хотя бы один файл пакета успешно обработан, но `batch.failed > 0` задаёт отдельное предупреждение «Готово с ошибками». Клиенты должны учитывать batch-итог, а не только значение state. Все ошибки в пакете дают `error` без скачивания пустого архива.

POST `/api/v1/jobs/{id}/continue` принимает JSON `{tool, options}`. Оригинал результата копируется в input новой задачи, не передаётся через внешний URL. Проверяются сессия, срок хранения до и после копирования, совместимость формата и размер. POST `/api/v1/history/clear` удаляет только terminal-задачи своей сессии. Общий пароль защищает в том числе OpenAPI, однако cookie API не заменяет будущие сервисные аккаунты.

`access.py` содержит необязательную проверку общего пароля и ограничитель попыток. Подписанные cookies не содержат пароль; токен доступа зависит от сохранённого хеша и ключа подписи. Смена хеша инвалидирует прежние токены доступа при следующих запросах. Logout очищает cookie текущего браузера, но не вводит серверный реестр отозванных копий cookies.

Хранение: входной документ, частный manifest, job scratch, рабочие файлы внутри output/.work и итог. Manifest/scratch/input удаляются в конце; восстановление после перезапуска убирает остатки terminal/running-задач. Логические квоты учитывают размер входа и резерв максимального результата, но не являются ограничением всех промежуточных байтов файловой системы. Health endpoint отвечает 503, если диспетчер очереди остановился.

Frontend использует hash-маршруты, включая `#/tools/{id}?source={jobId}`. Контекст обновляет доступность сервера, прерывая устаревшие запросы. PDF.js рендерит preview в браузере; просмотр защищённого документа требует пароля в памяти экрана. PageOrganizer держит только 24 миниатюры одновременно. История обновляется чаще при активных задачах и приостанавливает фоновый опрос в скрытой вкладке.

## Компрессор 0.3

`compression.py` заменяет прежнюю структурную оптимизацию PDF. Режимы `balanced`, `strong`, `lossless`, `custom` передаются через общий `ConvertOptions`. Изменяются поддерживаемые растровые XObjects, а не рендер всей страницы. Реальные размеры использования определяются по матрицам content streams и вложенных форм. pikepdf/QPDF и Pillow работают внутри прежнего ограниченного worker-процесса.

`pipeline` получает отчёт компрессии из промежуточного sidecar, переносит его в `details.json` одиночного результата либо в пофайловый отчёт batch. Worker публикует `details` вместе с результатом, SQLite получает аддитивную колонку `details`, API отдаёт `details.compression`. Исходные пароли в отчёт не включаются. No-op помечается отдельно и возвращает оригинальные байты.

Сравнение качества загружает только готовый результат по endpoint владельца; исходный File остаётся в памяти браузера. Повтор с другими настройками использует первоначальный файл, не последовательное ухудшение уже сжатого JPEG. Подробнее: COMPRESSION.md и QA-0.3.md.
