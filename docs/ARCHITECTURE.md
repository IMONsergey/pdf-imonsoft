# Архитектура первой сборки

## Границы модулей

`shared/tools.json` — проверяемая сервером матрица инструментов. Клиент отображает доступность, но сервер не доверяет клиентским расширениям/параметрам. `engines.py` — адаптеры, не HTTP-обработчики. `worker.py` — отдельный процесс с ограничениями. `jobs.py` — SQLite-состояние и диспетчер. `main.py` — HTTP, сессии, проверка загрузки и владения. React не содержит серверных секретов.

Состояния: queued → running → done/error/cancelled. Успешный результат появляется только после фактической проверки выходного файла. Файлы пишутся в каталог случайного job ID под именами `000.ext` и т. д. Пользовательские имена используются только для отображения, не как пути файловой системы. Пароли не записываются в SQLite: только во временный закрытый manifest для процесса конвертации, который удаляется после задачи.

SQLite использует WAL и короткие транзакции. Подключения закрываются после каждого действия. При перезапуске прерванные running-задачи получают понятную ошибку; queued-задачи продолжаются. Одна API-реплика владеет очередью, иначе возможна гонка восстановления/обработки. Горизонтальное масштабирование отложено до отдельного брокера.

PDFium не вызывается из параллельных потоков общего процесса: каждая задача получает отдельный процесс. Отмена убивает группу процессов вместе с дочерним OCR/локальным LibreOffice. Статусы — настоящие, нет имитации прогресса по таймеру. Office-движок вызывается только по настроенному серверному адресу, пользовательский URL не принимается.

## Хранение

Исходник → закрытый временный каталог → результат. Результат доступен только подписанной cookie-сессии, владеющей задачей. Нет возможности скачать по одному лишь знанию job ID. Автоудаление включает DB-запись и каталог; endpoint отказывает сразу после expiry. «Мои задачи» — не постоянный аккаунт и не межустройственная история.

## Расширение

Добавление операции: запись каталога → валидация параметров → адаптер с контрактом `execute(manifest, progress)` → тест входного/выходного формата → при необходимости параметры UI. Не включать плитки неработающих операций как будто они доступны. Экспериментальные конвертации должны иметь явную маркировку и проверку качества.

## Внешний API

OpenAPI: `/api/openapi.json`. Для запросов записи передавайте `X-IMONSOFT-Client: web`, сохраняйте cookie, используйте тот же origin. POST `/api/v1/jobs`: multipart `tool`, `options` (JSON-строка), `files` (повторяемое поле). Ответ 202 с job ID. GET job, POST cancel, DELETE job и GET download проверяют владельца. API keys и сервисные аккаунты — следующий этап, не притворяться, что browser cookie является полноценной API-аутентификацией.
