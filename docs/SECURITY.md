# Границы безопасности

## Что уже предусмотрено

- По умолчанию публикуется только `127.0.0.1:8080`; API и Gotenberg без host-портов.
- Внутренняя processing-сеть Docker без выхода в интернет; Gotenberg запрещает загрузку внешних ресурсов, webhook и Chromium routes.
- Контейнеры непривилегированные, read-only root, ограниченные память/CPU/число процессов, без Linux capabilities и без docker.sock.
- Размер проверяется reverse proxy и API, включая подсчёт полученных байтов. Ограничены файлы/страницы/пиксели/распаковка OOXML/время/память/output.
- Подписанная HttpOnly SameSite=Strict cookie, проверка владельца во всех job endpoint, CSRF-заголовок и same-origin проверка.
- Валидация формата по содержимому, временные случайные каталоги, пароли не передаются через URL или CLI.
- Входные файлы удаляются после задачи, результат и metadata — по TTL. Нет внешней аналитики или CDN в UI. По умолчанию выключен HTTP access-log API.

## Чего эта версия не гарантирует

Это не доказанный sandbox для враждебных файлов произвольных анонимных посетителей. Процессы одного API-контейнера имеют общий UID и файловую систему. Уязвимость парсера может нарушить границы задач внутри контейнера. Нужны отдельные ephemeral-контейнеры/VM на задачу или более строгий sandbox до многопользовательского публичного запуска.

Нет SSO, аккаунтов, серверных API-ключей, rate-limit по подтверждённому пользователю, админки или антивирусного заключения. Новая cookie позволяет создать новую анонимную сессию. Ограничение очереди не заменяет защиту от DoS. MIME/сигнатура файла не доказывает отсутствие вредоносного содержимого. Обработанный PDF не обязательно санитизирован от всех действий/вложений.

Данные на томе и в локальном dev не шифруются средствами приложения. Используйте шифрование диска, HTTPS, ограниченные резервные копии, правила удаления snapshots и ограничение доступа администраторов. «Удалено» означает логическое удаление приложением, а не гарантированное стирание с SSD и всех резервных копий.

## Перед публичным запуском

1. Добавить аутентификацию, tenant/user ownership, rate limiting и лимиты диска/заданий на пользователя и IP.
2. Проверить parser dependencies/SBOM/CVE и зафиксировать Docker image digests. Текущие теги версий не являются неизменяемыми digest.
3. Выделить обработку недоверенных документов в изолированные disposable workers. Отдельные пользователи/тома, network deny by default.
4. Настроить TLS и COOKIE_SECURE=true. Не открывать BIND_ADDRESS=0.0.0.0 без внешнего контроля доступа.
5. Нагрузочное тестирование, мониторинг диска/памяти, backpressure, журнал событий без содержимого документов и паролей.
6. Проверить внешние ссылки Office, архивные бомбы, повреждённые и зашифрованные документы, гонки отмены/удаления/скачивания, корректность жизненного цикла файлов.

Локальный `OFFICE_ENGINE=local` — для разработки на доверенных файлах. Без Docker этот процесс не получает сетевую изоляцию Compose.
