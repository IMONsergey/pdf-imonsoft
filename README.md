# IMONSOFT Files

Self-hosted платформа для PDF, презентаций, документов и изображений. Собственный русский интерфейс, светлая и тёмная темы, **33 операции**, пакетная обработка и последовательная работа с результатами. Без платного API и встраивания чужого сервиса.

**Два разных результата:** PDF → PowerPoint создаёт изображения страниц на слайдах, а PDF → Word экспортирует текстовый слой. Ни один из этих режимов не восстанавливает исходную редактируемую вёрстку. Ограничения показаны в интерфейсе и в результате обработки.

## Запуск

Нужны Docker и Docker Compose; рекомендуется выделить Docker не менее 5 ГБ памяти.

```bash
cp .env.example .env
docker compose up --build -d
```

Адрес: **http://127.0.0.1:8080**. По умолчанию порт доступен только на локальном компьютере. API и Gotenberg не публикуют порты. Первый запуск загружает зависимости, последующие используют кэш.

```bash
docker compose ps
docker compose logs --tail=80 api gotenberg
docker compose down                 # остановка без удаления данных
```

Не используйте `down -v` без необходимости: это удалит том с результатами и ключом сессий. Изменение лимитов или пароля требует пересоздания API: `docker compose up -d api`.

## Инструменты

| Раздел | Возможности |
|---|---|
| Презентации | PPT/PPTX/ODP → PDF; выбранные страницы PDF → PPTX в виде изображений |
| Страницы PDF | Объединение, визуальный порядок/поворот/удаление, извлечение по диапазону, разделение по группам, обрезка видимых полей |
| Подготовка PDF | Оптимизация, AES-256, снятие известного пароля, водяные знаки с углом/непрозрачностью, нумерация, очистка стандартных метаданных |
| Извлечение | Страницы → JPG/PNG; встроенные растровые изображения; текст → TXT/DOCX/Markdown; отчёт о структуре PDF |
| OCR и растрирование | Русский/английский OCR, выбор страниц и DPI; преобразование видимых страниц в растровый PDF |
| Office | DOC/DOCX/ODT/RTF → PDF; XLS/XLSX/ODS → PDF |
| Изображения | Сборка PDF, PNG/JPEG/WebP, пропорциональный размер, оптимизация, поворот, отражение, оттенки серого |

Полный реестр: `shared/tools.json`. Он используется интерфейсом и API, включая форматы, доступные настройки, предупреждения и поддержку batch/postprocess.

## Рабочие процессы

**Редактор страниц:** миниатюры, перетаскивание и кнопки изменения порядка, поворот, удаление, обратный порядок, восстановление исходного состояния, отмена/повтор. Не больше 24 миниатюр в одной группе. Исходник не меняется.

**Пакетная обработка:** несколько файлов с одинаковыми параметрами. Результат — ZIP, `report.json` и `readme.txt`. Частичный успех явно отмечается в интерфейсе и истории; ошибка одного файла не скрывается за зелёным общим статусом. Если не обработан ни один файл, задача завершается ошибкой.

**Следующий шаг:** готовый результат можно передать совместимому инструменту без повторной загрузки. Предпросмотр при этом получает копию результата с сервера в браузер. Проверяются владелец сессии, срок хранения, формат и входной лимит. ZIP-архивы автоматически не распаковываются.

**После конвертации:** Office → PDF и изображения → PDF могут сразу выполнить оптимизацию, водяной знак или нумерацию внутри одной задачи.

**История:** поиск по файлу/операции, фильтры состояния, скачивание, отмена и удаление. Очистка завершённых задач требует подтверждения и не прерывает активные задачи.

## Закрытое рабочее пространство

Вход по общему паролю необязателен и по умолчанию выключен. Это не учётные записи, не SSO и не совместная история: задачи всё равно принадлежат отдельной браузерной сессии.

```bash
docker compose exec api python -m app.access
```

Команда интерактивно запрашивает новый пароль дважды и выдаёт `ACCESS_PASSWORD_HASH=...`. Добавьте эту строку в локальный `.env`, затем выполните `docker compose up -d api`. Пароль в открытом виде не записывается. После выхода история прежней сессии становится недоступна; срок хранения файлов продолжает действовать. Для удалённого доступа необходим HTTPS с `COOKIE_SECURE=true`.

## Архитектура и границы

```text
Browser → Nginx → FastAPI + SQLite queue → отдельный процесс задачи
                                         ├─ pipeline: single / batch / finishing
                                         ├─ pypdf / PDFium / python-pptx / python-docx
                                         ├─ Pillow / Tesseract / ReportLab
                                         └─ внутренний Gotenberg → LibreOffice
```

React + TypeScript + Vite; Python + FastAPI; Docker Compose. Отдельный процесс позволяет остановить конвертацию, но **не является полной границей безопасности между задачами**. Процессы API/конвертации используют один контейнер и пользователя. Это версия для доверенной собственной инфраструктуры, не готовый анонимный публичный SaaS.

Перед публикацией нужны полноценная аутентификация, отдельные worker-контейнеры/песочницы, квоты по пользователю/IP, наблюдаемость и нагрузочная проверка. SQLite-очередь рассчитана на один диспетчер: нельзя масштабировать API несколькими Uvicorn workers или репликами с общим томом.

## Лимиты и удаление

По умолчанию: 50 МБ на входную загрузку, 20 файлов, 200 страниц в документе, 250 МБ результата, 180 секунд на всю задачу, 3 активные задачи на сессию. Для batch общий timeout не умножается на число файлов. Бюджет хранения: 4096 МБ на сервер и 1024 МБ на сессию; для активных задач резервируется место под результат. Это логический бюджет, а не жёсткая файловая квота временных данных.

Результат хранится 1 час **от загрузки**, затем скачивание запрещается; фоновое удаление имеет задержку до 30 секунд. Входные файлы, manifest с параметрами и рабочие временные файлы удаляются после выполнения, ошибки или отмены. Пароли документов не сохраняются в истории или localStorage; исходный пароль может оставаться в памяти открытого экрана для предпросмотра/повторной попытки до сброса или ухода со страницы.

Параметры заданы в `.env.example`. При увеличении входного лимита согласуйте `MAX_UPLOAD_MB`, `MAX_REQUEST_MB` и лимит тела запроса Gotenberg.

## Качество и ограничения

Office-экспорт зависит от установленных шрифтов, макетов и поддерживаемых эффектов. PDF не переносит анимацию и видео презентаций. DOCX/Markdown экспортируют только текст, без восстановления таблиц и многоколоночной вёрстки. Для сканов сначала нужен OCR.

Обрезка PDF меняет CropBox, но не удаляет скрытое содержимое: это **не редактирование конфиденциальных данных**. Растрирование удаляет текстовый слой, векторы, ссылки и формы. OCR может ошибаться. Очистка метаданных не является полной анонимизацией. Изменение подписанного PDF может нарушить его цифровую подпись. Оптимизация не гарантирует уменьшения уже сжатого файла.

## Брендинг

`apps/web/src/lib/brand.ts` задаёт название и подписи, `styles.css` содержит общие дизайн-токены и темы, `workflows.css` — стили редактора/пакетов/истории с теми же токенами. Знак находится в компоненте `Brand` и `public/favicon.svg`; метаданные страницы — в `index.html`. Нет внешней аналитики, рекламных запросов или загружаемых из интернета шрифтов.

## Разработка и проверки

Python 3.13+, Node 24. Вне Docker Office/OCR требуют установленных LibreOffice и Tesseract. Для доверенных синтетических файлов:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install --require-hashes -r services/api/requirements-dev.lock
cd services/api
OFFICE_ENGINE=local uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
# Другой терминал:
cd apps/web
npm ci
npm run dev
```

Vite: `http://127.0.0.1:4173`, API proxy: порт 8000. На macOS можно задать `LIBREOFFICE_BIN=/Applications/LibreOffice.app/Contents/MacOS/soffice`.

```bash
# Из корня с активированным Python-окружением:
(cd services/api && python -m pytest tests -q)
(cd apps/web && npm ci && npm run build)
python scripts/make-fixtures.py
(cd apps/web && npx playwright install chromium && npm run test:e2e)
# Браузерная проверка готового Docker-приложения:
(cd apps/web && E2E_BASE_URL=http://127.0.0.1:8080 npm run test:e2e)
```

Зависимости Python зафиксированы с хешами, Node — в package-lock.json. Изменяйте исходные `requirements*.txt`, затем обновляйте lockfiles командой `uv pip compile ... --generate-hashes --python-version 3.13` и повторяйте проверки. Не редактируйте хеши вручную.

Тесты проверяют содержимое PDF/DOCX/PPTX/ZIP, новые обработчики, ограничения, сессионную принадлежность, общий пароль, продолжение результата и удаление. Playwright проверяет реальные операции, редактор, batch, историю, все 33 экрана и автоматические правила доступности axe. UI-тест формы входа использует перехват API; проверка реального пароля выполняется отдельно серверными тестами. Автоматические проверки не заменяют тесты с реальными документами и проверку специалистом по доступности.
